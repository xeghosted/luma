One plugin, two games, live Lua

Luma is a GoldHEN plugin that boots a Lua 5.4 runtime inside a running RAGE game on a jailbroken PS4. It binds the game's own native functions as ordinary Lua functions and runs your code on the game thread, once per frame. 

on_tick(function()
    local ped = GET_PLAYER_PED(-1)
    local c   = GET_ENTITY_COORDS(ped, true)   -- Vector3 returns arrive as {x, y, z}
    if GET_ENTITY_HEALTH(ped) < 100 then
        SET_ENTITY_HEALTH(ped, GET_ENTITY_MAX_HEALTH(ped))
    end
end)

With the VS Code extension you save a file and it is running on the console a moment later. Scripts and resources reload live; only a new plugin binary needs a game restart.

The two games

Luma identifies the game it was loaded into by a byte signature and switches everything that differs behind one profile: native table, frame hook, data root, control port. The two data roots are deliberately separate — one console can host both, and a script must never land in the other game's scripts/ directory.

An unknown build does not load. An RVA is valid for exactly one build. On any other version those addresses point at something else and calling them crashes the game — so Luma refuses instead of guessing: it writes the bytes it actually found at the signature address into its log and stops. If your version is not one of the two above, this plugin is not for it yet.

What it can do

  • Call any native the build registers, by its canonical name, with types marshalled for you — ints, floats, bools, strings, pointers and Vector3.
  • Run per-frame code on the game thread through on_tick.
  • Resources in the familiar shape: a folder with an fxmanifest.lua, CreateThread, Wait, events, exports, and start/stop/restart at runtime.
  • Live editing over a TCP control channel: push a file, reload the script directory or restart one resource, evaluate an expression, stream the log.
  • Autocomplete for every native, from generated LuaLS definitions.

What it deliberately does not do

  • Nothing online. This is for single-player. Using it anywhere else is your problem and a fast route to a ban.
  • No authentication by default. Anyone who can reach the control port can run arbitrary Lua inside the game — the same trust level GoldHEN's FTP already grants on the same network. There is a token if you want one.
  • No script globals on RDR2. The block table has not been located in that build, so those two functions raise rather than read and write an address derived from nothing.

Proven on hardware

Both games, from their own boot logs:

[profile] Grand Theft Auto V (CUSA00411), data root /data/gtalua/, port 9615
[hash_natives] walked table: 6691 natives, 0 rejected
[hash_natives] GET_HASH_KEY -> 0x72B71C36 (OK, table usable)

[profile] Red Dead Redemption 2 (CUSA03041), data root /data/rdr2lua/, port 9616
[hash_natives] 7072 natives compiled in; GET_HASH_KEY -> 0x3DBB3D48 (OK)
player model is 2.01 m tall

Each line settles something different — the hash check proves the address arithmetic, the frame hook proves the detour survived relocation, and 2.01 m tall proves Vector3 out-parameters, which is the path that silently returned zeroes for a long time. The full account is in Internals.
