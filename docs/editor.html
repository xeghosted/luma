The editor half

RAGE Script Manager is a VS Code extension that talks to Luma's control channel. Save a file, press Ctrl+Alt+R, and the script is on the console and running before you have let go of the key. Errors come back as squiggles on the line that raised them.

Install from the Marketplace · Source 

code --install-extension DominikHeise.rage-script-manager

One extension serves both games, and needed no game-specific code to do it: it never builds console paths. It sends relative ones — scripts/<name>, resources/<name>/<rel> — and the plugin resolves them under whichever game's data root it detected at boot. The port is the only thing that distinguishes them.

Setting it up

  1. Deploy Luma and start the game — see Install.
  2. Set rageScriptManager.host to your console's IP.
  3. Set rageScriptManager.port: 9615 for GTA V, 9616 for RDR2.
  4. Run RAGE: Connect.

Both are workspace settings, so a GTA V workspace and an RDR2 workspace can sit open side by side without either pointing at the wrong game.

SettingDefault
rageScriptManager.hostemptyConsole IP or hostname. You must set this.
rageScriptManager.port96159615 for GTA V, 9616 for RDR2.
rageScriptManager.tokenemptyShared secret, if the console has a token file.

Push & Restart decides where a file belongs by its path. Something under resources/<name>/ is written there and that resource is restarted; anything else goes to scripts/ and reloads the script directory.

The console

RAGE: Open Console gives you a REPL evaluating Lua in the same state your scripts run in — the same globals, the same natives, the same everything. A leading = makes it print the value: 

= GET_ENTITY_HEALTH(GET_PLAYER_PED(-1))
200
= natives_ready()
true
SET_ENTITY_COORDS(GET_PLAYER_PED(-1), 0.0, 0.0, 100.0, false, false, false, true)

This is the fastest way to find out what a native actually does, and the fastest way to crash the game — the call runs on the game thread with whatever types you gave it.

Without VS Code

tools/console.ps1 speaks the same protocol from a shell, which is useful for scripting a deploy or for checking something without an editor open: 

pwsh tools/console.ps1 hello   -Ip 192.168.1.50 -Port 9615
pwsh tools/console.ps1 reload  -Ip 192.168.1.50 -Port 9615
pwsh tools/console.ps1 exec    "return 1 + 1" -Ip 192.168.1.50 -Port 9615
pwsh tools/console.ps1 reslist -Ip 192.168.1.50 -Port 9615
pwsh tools/console.ps1 log     -Ip 192.168.1.50 -Port 9615
The channel serves one client at a time. Run Disconnect before pointing another tool at the same port, or the second connection is accepted and then never answered — which looks exactly like a hang, not like a busy signal.

Autocomplete

Native autocomplete comes from the plugin project, not from the extension: editor/lua-defs/<game>/ holds tens of thousands of generated lines per game, which is why they live with the game they describe rather than being bundled into an extension that serves both. New Resource writes a .luarc.json pointing at them. You need sumneko.lua.

The extension knows about those files only well enough to refuse to push one to the console — a type stub in scripts/ would be run on every boot from then on.
