Luma Lua scripting for RAGE games on PS4
Overview Install Scripting Editor Internals GitHub

Install

Build the plugin, push it and one game's scripts to the console, list it in plugins.ini, start the game. Then read the log, because the log is how you find out whether any of it worked.

What you need

  • A PS4 running GoldHEN, with its FTP server reachable (port 2121).
  • Grand Theft Auto V CUSA00411 v1.57 or Red Dead Redemption 2 CUSA03041 v1.32. Other versions are refused — see why.
  • The OpenOrbis PS4 Toolchain, to build. It is a Linux toolchain, so on Windows build under WSL.
  • PowerShell 7 for tools/deploy.ps1, or any FTP client if you would rather copy the files yourself.

1. Build

OO_PS4_TOOLCHAIN must point at the toolchain; build.sh refuses without it rather than producing something subtly wrong. 

export OO_PS4_TOOLCHAIN=/path/to/OpenOrbis/PS4Toolchain
./build.sh
# -> build/Luma.prx   the plugin, fake-signed
# -> build/Luma.elf   the same image unsigned, useful for inspection

On Windows, from the repository root:

wsl -e bash -lc "cd /mnt/c/path/to/Luma && \
  export OO_PS4_TOOLCHAIN=/mnt/c/PS4/OpenOrbis/PS4Toolchain && ./build.sh"

The build ends with a post-link check that the image carries no .init_array. That is not ceremony: this plugin runs no static initialisers, so a file-scope object with a constructor would be silently dead code, and the linker is the only thing that can see it.

Run the tests first

bash tests/run.sh

Everything below the ORBIS line is plain C++ and Lua, so most of the plugin is exercised on a PC: the native bridge and its marshalling, the wire codec, the resource model, the scheduler, and the generated bindings against a fresh regeneration. It also re-checks that each profile's frame hook is still safe to detour. If this is red, do not deploy.

2. Push it to the console

pwsh tools/deploy.ps1 -Ip 192.168.1.50 -Game gta5     # or -Game rdr2

-Game picks both ends at once — which scripts are sent and which data root they go to — so one game's natives.lua can never reach the other's directory. That separation is structural, not a flag you have to remember.

Flag
-IpYour console's address. Required; there is no default, because a default that is not your console fails as a connection timeout rather than as a missing argument.
-Gamegta5 or rdr2. Defaults to rdr2.
-PrxOnlySend only the plugin, leaving the scripts on the console alone.
-SkipPrxSend only the scripts and resources.
-PortFTP port, default 2121.

What lands where:

/data/GoldHEN/plugins/Luma.prx    the plugin — one file, both games

/data/gtalua/natives.lua          generated bindings, loaded before your scripts
/data/gtalua/scripts/*.lua        your flat scripts, loaded in directory order
/data/gtalua/resources/<name>/    resources, each with an fxmanifest.lua
/data/gtalua/autostart.cfg        resources to start at boot, one name per line
/data/gtalua/gtalua.log           log() / print() / notify() output, and load errors
/data/gtalua/token                optional shared secret for the control channel

/data/rdr2lua/…                   the same shape, for Red Dead Redemption 2
Replacing the plugin is not a plain upload. GoldHEN keeps Luma.prx mapped in every game it is loaded into. Overwriting it in place succeeds and can leave the file holding neither the old build nor the new one. deploy.ps1 therefore stages the file beside the target and renames over it: the unlink drops only the directory entry, the running game keeps the copy it already mapped, and the new name points at a file that was never written while in use. If you copy the plugin by hand, do the same — or close the game first.

3. List it in plugins.ini

Edit /data/GoldHEN/plugins.ini and name the plugin under each game's title id. The same file serves both: 

[CUSA00411]
/data/GoldHEN/plugins/Luma.prx

[CUSA03041]
/data/GoldHEN/plugins/Luma.prx

The plugin is mapped at title launch. Start the game — or restart it, if it was already running.

4. Read the first boot

Fetch the log over FTP, or use RAGE: Show Log in the editor. A healthy GTA V boot looks like this: 

[profile] Grand Theft Auto V (CUSA00411), data root /data/gtalua/, port 9615
[Boot] luma: ready
[hash_natives] walked table: 6691 natives, 0 rejected
[hash_natives] GET_HASH_KEY -> 0x72B71C36 (OK, table usable)
[natives] hash registry ready: 6691 natives (attempt 1)
hello.lua loaded; hash registry ready: true
[resource] started hello

The three lines that actually matter, in order:

  • [profile] … — Luma recognised the build. If this line is missing, nothing else will work; see below.
  • GET_HASH_KEY -> 0x… (OK) — Luma asked the game to hash a known string and the game returned the value Luma predicted. That single line proves the image base, the addresses and the call ABI all agree.
  • [Boot] luma: ready — the frame hook is installed and running on the game thread.

When it does not work

The log says no known build matched

[profile] no known build matched. At rva 0xAA9310 this image has
          55 48 89 E5 41 56 53 49 - Luma supports CUSA00411 v1.57
          and CUSA03041 v1.32 only

Your game version is not one of the two supported builds, and Luma stopped rather than call addresses belonging to a different executable. The bytes in the message are what it actually found, which is the useful half: they identify the build to whoever wants to add it. There is no flag to force it, deliberately.

There is no log at all

The plugin never loaded. Check plugins.ini names the right path under the right title id, that /data/GoldHEN/plugins/Luma.prx exists and is the size your build produced, and that you restarted the game after adding it.

The game boots, then crashes a few seconds in

Almost always a script, not the plugin — the frame hook runs your on_tick on the game thread, so a native called with the wrong argument types crashes the game rather than raising. Move /data/<game>/scripts/ aside and boot clean to confirm, then reintroduce one script at a time. The signature table is what to check.

The editor connects and then hangs

The control channel serves one client at a time. A second connection is accepted and never answered, which looks exactly like a hang. Disconnect whatever else is attached — including tools/console.ps1.

Uninstalling

Remove the plugin's line from plugins.ini and restart the game. Delete /data/GoldHEN/plugins/Luma.prx and the game's data root if you want the scripts gone too. Luma writes nothing outside those two places and modifies nothing on disk that belongs to the game.
